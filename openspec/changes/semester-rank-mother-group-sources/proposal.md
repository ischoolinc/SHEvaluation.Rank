# Proposal

## Why

學期成績固定排名只能用「目前一般生」的班級、科別與標籤當母群，而且計算學年度、學期鎖在系統預設值。學校需要沿用歷史母群或 Excel 名單，計算另一個學年度學期的成績，並在計算前決定每位學生的五種排名是否參與。參與狀態必須在排名與統計之前生效，舊批次的排名公式與資料表格式仍要相容。

## What Changes

- 計算學年度、學期可選擇，預設為系統目前值；此期間只決定成績，與歷史母群來源期間分開。
- 新增三種母群來源：依目前學生資料產生（預設）、歷史學期固定排名批次、Excel 母群清單。
- 新增確認母群步驟。五種母群名稱唯讀，五種參與狀態可個別或多選調整。計算只讀確認後的最終設定。
- 三種來源都先保留來源原本的五種母群名稱與參與狀態，再套用圖1不排名學生類別。符合者五種排名預設不參與，圖2可再修改；計算只使用圖2最終值。這條規則不改來源名稱，也不回寫舊歷史批次。
- 類別一、類別二名稱空白時預設不參與，不建立空白名稱的類別排名母群。
- 歷史批次有快照時先讀快照；沒有快照時只從既有排名資料還原。同一學生、同一排名類型若還原出多個不同母群名稱，不任取一筆、不用目前資料覆蓋，並在畫面上警示。無法還原的母群留空、該項預設不參與。沒有本次成績的歷史學生仍留在確認清單，該成績項目不產生名次。
- 歷史清單可手動加入學生，帶入目前五種母群名稱，參與狀態可再調整。
- Excel 以學號加學生狀態對應 `student.student_number` 與 `student.status`，取得唯一的 `student.id`。狀態只接受一般、延修、休學、輟學、畢業或離校、刪除。查無、空白、狀態無法對照、同一學號同一狀態重複、同一學生識別重複，或查到多筆時，整份不得進入計算。相同學號但狀態不同可以各自匯入。匯入與匯出使用同一組 13 欄。
- 新批次的母群快照改寫入既有 `rank_batch.extension` JSONB 陣列，`extension_name` 為 `MotherGroupSnapshot`、`version` 為整數 1。內容是確認清單的全部學生、學號、姓名、可解析的排名年級、五種母群名稱與 JSON boolean 參與狀態。`rank_batch.setting` 保留原有 XML 計算設定，新批次不再把快照寫進 setting。舊批次仍可讀 setting 裡的 XML 快照；兩種快照都沒有時，才用 `rank_batch_student` 還原。不新增資料表、不改排名公式或其他排名表結構。
- 五種排名的排除在 `RANK`、`COUNT`、標準差、百分位與五標之前生效。
- 停用舊有效排名與啟用新排名放在同一次資料庫交易。交易完成前不影響舊有效排名；交易失敗則舊有效排名保持原狀。不得因部分 SQL 提交而留下不完整的有效排名，也不得使用批次 ID 0。
- 開啟學期成績固定排名時，既有左下角說明位置持續顯示畫面初始化、學校設定、學生類別、學生清單與年級清單。五段都成功才恢復原本說明並允許下一步；任一階段失敗則顯示錯誤，下一步維持停用。學生篩選與擇優設定規則不變。
- 下一步進行中不可重入。三種母群來源都立刻停用下一步，並在既有左下角顯示該來源的處理文字。第二頁開啟後才解除進行旗標，第一頁維持停用；回到第一頁或取消、失敗、沒有資料時才恢復下一步與原本說明。Excel 選檔留在畫面執行緒，解析與查詢改在背景工作，成功後才顯示確認清單。
- 正式排名的 `student_list` 改由確認清單工作副本組成一份 JSON 陣列，再用 PostgreSQL 9.6 已有的 `jsonb_to_recordset` 展開。三種母群來源共用這條路徑。不再為每位學生產生 `SELECT` 後以 `UNION ALL` 接成學生清單。科目、分項、擇優、排名與統計公式，以及四張排名表的寫入與單一語句回復，維持不變。這份 SQL 輸入 JSON 不寫進 `rank_batch.extension`。
- 資料物件及其關聯屬性在確認可離開畫面執行緒之前，仍在畫面執行緒讀取。階段文字必須先顯示，避免讀取堵在說明出現之前。
- 排名寫入前增加確認框，顯示圖1學年度、學期、母群來源，以及會停用的有效學期成績排名。取消時不儲存擇優組態、不執行排名 SQL。執行中不可重複進入計算。
- 實際寫入維持關閉，直到獨立測試資料庫上的 PostgreSQL 9.6 與 17.1 必要證據全部通過。測試包含三種母群來源、五種參與、四張排名表、成功後的回復，以及故意失敗。故意失敗必須先處理 PostgreSQL 已中止的交易。正式學校資料庫不用於首次寫入測試。證據通過後才開放寫入，並同時更新原本要求寫入保持關閉的靜態檢查。失敗仍不可顯示成功。排名公式與三種母群來源規則不變。

## Capabilities

### New Capabilities

- `semester-rank-mother-group-source`: 計算期間、預設的目前學生來源，以及三種來源共同的名單與母群名稱產生規則。
- `semester-rank-participation`: 確認母群、五種參與、不排名預設、人數統計，以及手動加入學生。
- `semester-rank-excel-exchange`: Excel 匯入驗證、學號加學生狀態的唯一對應，以及同格式 13 欄匯出。
- `semester-rank-history-restore`: 歷史學期批次選擇、快照還原、無快照還原與缺漏警示。
- `semester-rank-calculation`: 參與集合在排名統計前生效、舊公式相容、JSONB 母群快照與舊 XML 相容，以及成功與失敗的資料一致性。另含寫入前確認、執行中防重複、驗證完成前不寫入，以及測試證據通過後才開放寫入。
- `semester-rank-screen-load`: 學期成績固定排名初次開啟時的左下角載入階段、完成後恢復說明、失敗時停在條件頁，以及資料讀取的執行緒限制。

### Modified Capabilities

- 無。主 spec 目錄目前沒有既有能力。

## Impact

- 主要改 `CalculateSemesterAssessmentRank.cs`、`.Designer.cs`、`.resx`，以及新的母群來源類別；`SHEvaluation.Rank.csproj` 要納入新檔。
- 功能入口維持 `Program.cs` 的「學期成績排名計算」。定期評量與技職繁星不在本次範圍。
- 寫入仍使用 `rank_batch`、`rank_batch_student`、`rank_matrix`、`rank_detail`。新批次的 `setting` 維持原 XML 計算設定，母群快照改放既有 `extension` JSONB。不新增欄位、不改其他排名表結構。
- Excel 使用既有 Aspose.Cells 7.7.1。SQL 維持 PostgreSQL 9.6 到 17.1 可用的寫法，執行環境維持 .NET Framework 4.8。
- `SemesterAssessmentRankSelect` 仍只讀 `is_alive = true` 的排名。未公布的新批次不得出現在檢索結果。
- 載入狀態沿用條件頁左下角既有說明，不新增視窗。寫入保護、測試庫驗證與開放寫入都落在既有計算按鈕；開放前不改 `SemesterRankWriteGate` 的關閉結果。
- 首次寫入測試只使用獨立的 PostgreSQL 9.6 與 17.1。不把正式學校資料庫連線寫入 `App.config`。
- 已記錄的三項歷史來源遺留維持獨立，不併入載入狀態、寫入保護、測試驗證或開放寫入。
- 既有 Task 1～7 已確認的行為不變。尚未完成的 PostgreSQL 與畫面驗收維持未完成，直到該項自己的驗收通過。
