# Spec Delta

## Purpose

定義確認母群畫面如何顯示五種母群、調整參與狀態，以及哪些預設規則會先寫入這份清單。

## ADDED Requirements

### Requirement: 三種來源都先保留原值再套用不排名預設
目前學生、有效 JSON 歷史快照與 Excel MUST 先取得來源原本的五種母群名稱與參與狀態。系統接著 MUST 套用圖1不排名學生類別：符合者五種初始參與為不參與，五種母群名稱維持來源原值。沒有 JSON 的歷史學生清單不適用這條年、科、班原值規則，改依「沒有 JSON 的年科班預設參與且類別維持原規則」。使用者 MUST 能在確認清單改回參與。系統 MUST NOT 因這條規則修改來源名稱，也 MUST NOT 回寫舊歷史批次。

#### Scenario: 快照中的參與被本次不排名預設改寫
- **WHEN** 歷史快照記錄某生五種排名都參與，且該生符合圖1不排名學生類別
- **THEN** 確認清單保留快照中的五種母群名稱，五種初始參與為不參與，舊批次內容不變

#### Scenario: 不排名學生仍可被改為參與
- **WHEN** 學生符合不排名學生類別，使用者在確認清單把年排名改為參與
- **THEN** 該生仍顯示來源原本的年排名母群名稱，且年排名參與狀態為參與

#### Scenario: 未覆寫時維持不參與
- **WHEN** 學生符合不排名學生類別，且使用者未改任何參與狀態
- **THEN** 該生五種排名都是不參與

### Requirement: 類別母群空白時不建立排名群
類別一或類別二母群名稱為空白時，該項初始參與狀態 MUST 為不參與。系統 MUST NOT 為空白類別名稱建立排名母群。

#### Scenario: 學生沒有類別一標籤
- **WHEN** 目前學生來源產生的類別一母群名稱為空白
- **THEN** 類別一參與狀態為不參與，且不會出現空白名稱的類別一名次

### Requirement: 母群名稱唯讀且參與狀態可批次調整
確認清單的五種母群名稱 MUST 為唯讀。五種參與狀態 MUST 可個別修改，也 MUST 可對多選學生一次設定同一種排名的參與或排除。未按計算前，這些修改 MUST NOT 寫入排名資料表。

#### Scenario: 多選只改班排名參與
- **WHEN** 使用者多選學生並將班排名設為不參與
- **THEN** 這些學生的班排名為不參與，其餘四種參與狀態與全部母群名稱維持原值

#### Scenario: 還原初始設定
- **WHEN** 使用者已修改參與狀態後執行還原
- **THEN** 參與狀態回到進入確認清單時的初始值，母群名稱不變

### Requirement: 人數統計不查成績
確認清單 MUST 顯示五種排名各自的母群總人數、參與人數與排除人數。母群總人數 MUST 計算名稱相同的學生，包含不參與者。空白名稱 MUST NOT 計入具名母群。這些人數 MUST NOT 預先查詢成績。

#### Scenario: 同名母群同時包含參與與排除
- **WHEN** 同一班排名母群有 10 人，其中 8 人參與、2 人不參與
- **THEN** 該班母群總人數為 10、參與人數為 8、排除人數為 2

### Requirement: 計算只使用確認清單最終值
排名計算 MUST 只使用計算開始時已提交的確認清單母群名稱與參與狀態。來源產生規則與不排名預設 MUST NOT 在計算時再次覆寫使用者已調整的值。計算開始後對畫面清單的修改 MUST NOT 改變這次計算。

#### Scenario: 使用者覆寫不排名預設
- **WHEN** 不排名學生被改為參與科排名後開始計算
- **THEN** 科排名計算包含該生，不排名類別規則不再把他排除

#### Scenario: 計算開始後的畫面修改不追溯
- **WHEN** 計算已經開始，使用者再把該生科排名改為不參與
- **THEN** 這次科排名仍包含該生

### Requirement: 歷史清單可加入目前學生母群
歷史來源的確認清單 MUST 允許手動加入尚未在清單中的學生。加入時 MUST 帶入該生目前的五種母群名稱，並套用與新名單相同的初始參與規則。加入後母群名稱 MUST 唯讀，參與狀態 MUST 可調整。

#### Scenario: 加入不在歷史批次中的學生
- **WHEN** 使用者在歷史確認清單加入一名目前有班級與科別的學生
- **THEN** 該生出現在清單中，五種母群名稱來自目前學生資料，且參與狀態可再修改

### Requirement: 歷史加入學生仍只依學號
Excel 13 欄與 Task 10.2 MUST NOT 修改歷史加入學生。目前加入 MUST 仍只以 `student.student_number` 查詢。同一學號對到多位學生時 MUST 阻擋加入，不任選一筆。確認清單已有不同 `student.id` 但學號相同時，既有去重規則可能把另一位學生視為已在清單。這項限制 MUST 獨立保留。日後若調整，確認清單內的唯一識別 MUST 使用 `student.id`，MUST NOT 只使用學號。

#### Scenario: 相同學號有多位學生
- **WHEN** 使用者在歷史確認清單輸入一個對到多位學生的學號
- **THEN** 系統不加入任何一筆

#### Scenario: 清單已有相同學號的另一位學生
- **WHEN** 歷史確認清單已有一名學生，另一名不同 `student.id` 的學生使用相同學號
- **THEN** 目前規則可能視為已在清單而不加入；這次不改成以 `student.id` 判斷

### Requirement: 沒有 JSON 的年科班預設參與且類別維持原規則
類別一與類別二的初始參與 MUST 維持既有規則，不因歷史清單沒有 JSON 而改成預設參與。沒有 JSON 時，年、科、班 MUST NOT 沿用這三項的歷史參與狀態。不符合不排名類別者 MUST 預設參與；空白或衝突 MUST NOT 自動取消這三項。不排名類別的優先序尚未核准。核准前，符合者 MUST NOT 因全參與預設改成參與；這只是暫時保留既有效果。手動還原參與 MUST 沿用進入確認清單時的初始值，MUST NOT 另做一套回到歷史旗標的基準。

#### Scenario: 類別空白不因沒有 JSON 而改成參與
- **WHEN** 歷史批次沒有 JSON，學生的類別一名稱為空白，年排名名稱是「1年級」
- **THEN** 類別一仍不參與，年排名預設參與

#### Scenario: 計算使用第二畫面最終勾選
- **WHEN** 沒有 JSON 的年排名初始參與，使用者在第二畫面取消勾選後開始計算
- **THEN** 這次年排名不包含該生
