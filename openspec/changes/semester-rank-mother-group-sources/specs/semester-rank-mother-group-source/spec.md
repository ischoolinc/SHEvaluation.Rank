# Spec Delta

## Purpose

定義學期成績固定排名的計算期間，以及三種母群來源如何產生可確認的學生母群名單。

## ADDED Requirements

### Requirement: 計算期間可選且與母群來源期間分開
系統開啟時 MUST 以系統目前學年度與學期作為計算期間。歷史來源與 Excel 來源 MUST 讓使用者編輯本次成績的學年度與學期。目前學生來源 MUST 維持既有政策：恢復系統目前學年度與學期，並停用這兩個欄位。歷史期間與批次選取 MUST NOT 額外改寫計算期間；切換來源仍依各來源原有政策處理。

#### Scenario: 開啟畫面時使用系統預設期間
- **WHEN** 使用者開啟學期成績排名計算
- **THEN** 計算學年度與學期顯示系統目前值

#### Scenario: 歷史來源期間不同於計算期間
- **WHEN** 使用者以歷史來源期間 114 學年度第 2 學期選取母群，並將計算期間設為 115 學年度第 1 學期
- **THEN** 學生母群來自 114-2 批次，成績只取 115-1，而且選取批次不會改寫 115-1

### Requirement: 依母群來源顯示適用欄位
最上方學年度、學期 MUST 標成計算學年度、計算學期，並說明這組期間用於讀取學期成績與產生排名。三種來源 MUST 都保留計算年級、不排名學生類別與學期科目成績擇優採計。歷史來源學年度、歷史來源學期與歷史批次 MUST 只在歷史來源顯示，切換離開時 MUST 一併隱藏標籤與控制項。類別排名一、類別排名二 MUST 只在目前學生來源顯示。Excel 來源 MUST 顯示下載匯入範本與填寫說明，並把下一步改成「選擇 Excel 檔案」。

年級旁的說明 MUST 依來源改變：目前學生是依學生目前班級的年級篩選；歷史來源是依歷史母群的年排名母群判定年級，再套用勾選範圍；Excel 是依 Excel 的年排名母群判定年級，再套用勾選範圍。歷史與 Excel 名單中無法判定年級的學生 MUST 留在確認清單，並沿用既有計算前提示與略過規則。

#### Scenario: 三種來源的專屬欄位
- **WHEN** 使用者逐一切換目前學生、歷史學期成績排名與 Excel 母群清單
- **THEN** 計算年級、不排名學生類別與擇優採計都保留；歷史期間與批次只在歷史來源出現；類別排名一、二只在目前學生出現；Excel 顯示下載匯入範本、填寫說明，而且按鈕文字是「選擇 Excel 檔案」

### Requirement: 歷史與 Excel 共用可編輯的計算期間
歷史與 Excel MUST 共用使用者選好的計算期間。切入目前學生來源時 MUST 顯示系統目前學年度、學期並停用欄位。再切回歷史或 Excel 時 MUST 恢復先前可編輯的計算期間，不得沿用剛才顯示的系統期間蓋掉它。歷史期間與批次選取 MUST NOT 改寫這組計算期間。

#### Scenario: 切回歷史或 Excel 時恢復計算期間
- **WHEN** 使用者在歷史或 Excel 把計算期間設為 115 學年度第 1 學期，改選目前學生後看到系統目前學年期，再切回歷史或 Excel
- **THEN** 計算期間恢復 115 學年度第 1 學期，而且可以再編輯

### Requirement: 預設來源為目前學生資料
系統 SHALL 以「依目前學生資料產生」作為預設母群來源，並保留年級勾選、不排名學生類別、類別排名一、類別排名二與學期科目成績擇優採計設定。

#### Scenario: 未改來源直接產生名單
- **WHEN** 使用者保留預設來源並進入確認母群
- **THEN** 名單使用目前學生資料與畫面上的年級、類別和擇優設定

### Requirement: 目前學生來源沿用既有篩選與母群名稱
目前學生來源 MUST 只含狀態為一般、有班級且班級年級有值的學生，再套用勾選年級。年排名名稱 MUST 為目前班級年級，班排名名稱 MUST 為目前班級名稱，科排名名稱 MUST 來自學生科別，沒有學生科別時使用班級科別。類別一與類別二 MUST 沿用原有多標籤 `First()` 選取結果。

#### Scenario: 學生沒有個人科別
- **WHEN** 目前學生來源產生一名沒有個人科別、班級有科別的學生
- **THEN** 該生科排名母群名稱等於班級科別名稱

#### Scenario: 同一類別有多個標籤
- **WHEN** 學生在所選類別一底下有多個標籤
- **THEN** 類別一母群名稱等於原有 `First()` 選到的那一個標籤名稱

### Requirement: 三種來源使用同一筆學生母群資料
每一種來源 MUST 為每位學生產出同一組資料：系統學生 ID、學號、姓名、年、班、科、類別一、類別二的母群名稱，以及這五種排名各自的參與狀態。同一學生在同一種排名 MUST 只有一個母群名稱。

#### Scenario: 來源不同但確認畫面欄位相同
- **WHEN** 使用者分別由目前學生、歷史批次或通過驗證的 Excel 產生名單
- **THEN** 確認畫面都顯示同一組五種母群名稱與五種參與狀態欄位

### Requirement: 學生狀態不進入排名與快照
`StudentMotherGroup.Status` MAY 為可空整數，值是 `student.status`，供 Excel 識別與匯出第 3 欄使用。排名 SQL MUST NOT 讀取學生狀態。JSON 與舊 XML 母群快照 MUST NOT 儲存學生狀態或不排名類別。目前學生來源 MUST 仍只含狀態為一般的學生，並把既有狀態抄入 `Status`。歷史快照還原 MUST NOT 從快照推測學生狀態，還原後 `Status` MAY 為空。匯出前若 `Status` 沒有值，系統 MUST 只以 `student.id` 查詢目前的 `student.status`，而且 MUST 把所有缺值的 id 放在同一句查詢。這個值是目前學生主檔的狀態，不是歷史排名當時的狀態。查詢 MUST NOT 改歷史母群名稱或參與狀態，也 MUST NOT 依學號猜測狀態。

#### Scenario: 快照不含學生狀態
- **WHEN** 系統寫入或讀回 JSON 或舊 XML 版本 1 快照
- **THEN** 快照有來源、學生識別、學號、姓名與五種母群名稱及參與狀態，JSON 另有可解析年級或 null，但沒有學生狀態或不排名類別

#### Scenario: 歷史名單匯出補目前狀態
- **WHEN** 歷史確認清單的學生沒有 `Status`，而且這些 `student.id` 在學生主檔各有一筆允許的狀態
- **THEN** 匯出使用該筆目前狀態，母群名稱與參與狀態保持原值
