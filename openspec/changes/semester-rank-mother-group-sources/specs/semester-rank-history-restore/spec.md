# Spec Delta

## Purpose

定義如何選擇歷史學期固定排名批次，以及有快照與沒有快照時如何還原母群且不拿目前學生資料填補缺口。

## ADDED Requirements

### Requirement: 列出全部歷史學期固定排名批次
系統 MUST 列出既有的學期固定排名批次供選擇，包含該批的學年度、學期、批次說明與是否已有母群快照。清單 MUST 包含已不是目前有效排名的舊批次，且 MUST NOT 把定期評量或技職繁星批次當作學期母群來源。

#### Scenario: 同學年期有多個舊批次
- **WHEN** 同一學年度學期存在多筆學期成績排名批次
- **THEN** 這些批次都出現在歷史來源清單，使用者可指定其中一筆

#### Scenario: 技職繁星批次不出現
- **WHEN** 使用者開啟歷史學期母群清單
- **THEN** 考試名稱不是學期成績的排名批次不在清單中

### Requirement: 有快照時先讀來源原值
歷史批次 MUST 先讀 `rank_batch.extension` 的 `MotherGroupSnapshot`。JSON 快照可讀時，系統 MUST 以它作為來源原值，包含全部學生、姓名、五種母群名稱與五種參與狀態。讀取 MUST NOT 用目前班級、科別或標籤重建母群，也 MUST NOT 修改該舊批次。圖1不排名預設在來源原值之後另套用。

#### Scenario: JSON 快照原值先被保留
- **WHEN** 所選批次的 JSON 快照記錄某生有班排名母群名稱且班排名不參與，且該生不符合圖1不排名類別
- **THEN** 確認清單顯示該名稱與姓名，班排名初始狀態為不參與，舊批次內容不變

#### Scenario: 快照原值先被保留
- **WHEN** extension 沒有母群快照，setting 的 XML 版本 1 記錄某生有班排名母群名稱且班排名不參與，且該生不符合圖1不排名類別
- **THEN** 確認清單顯示該名稱，班排名初始狀態為不參與，舊批次內容不變

### Requirement: 壞掉的 JSON 快照不可改走其他來源
extension 不是 JSON 陣列、`MotherGroupSnapshot` 版本不是整數 1、學生內容無法還原、學生清單是空的，或同名快照超過一筆時，系統 MUST 顯示具體原因並停止。這種情況 MUST NOT 改讀舊 XML、`rank_batch_student` 或目前學生。extension 是 null、空白、`[]` 或有效陣列中沒有這個名稱時，才 MUST 繼續讀舊 XML。

#### Scenario: 版本不符時停止
- **WHEN** extension 有一筆 `MotherGroupSnapshot` 且版本不是整數 1，setting 另有可讀的 XML 版本 1
- **THEN** 確認清單不開啟，也不使用該 XML 快照

#### Scenario: 沒有 JSON 時讀舊 XML
- **WHEN** extension 是空陣列，setting 有一筆可讀的 XML 版本 1
- **THEN** 確認清單使用該 XML 快照，舊批次內容不變

### Requirement: 無快照時只從排名學生列還原
JSON 與 XML 都沒有母群快照時，系統 MUST 只以所選 `rank_batch.id` 的 `rank_batch_student` 還原，並以左外連接取得目前學號與姓名。年、科、班、類別一、類別二 MUST 分別使用 `matrix_grade`、`matrix_dept`、`matrix_class`、`matrix_tag1`、`matrix_tag2`。有非空白名稱的項目 MUST 預設參與；空白名稱 MUST 保持空白、該項不參與，並 MUST 在確認清單前提示。系統 MUST NOT 用目前班級、科別、標籤或排名明細推測名稱，也 MUST NOT 因學生目前沒有班級或已非在學而排除。沒有任何排名學生列時 MUST 提示並停止，不開啟空白確認清單，也不執行排名計算。

#### Scenario: 有名稱的母群預設參與
- **WHEN** 舊批次沒有快照，且排名學生列的班排名名稱是「高一甲」、科別是空白
- **THEN** 班排名名稱為「高一甲」且初始參與，科排名名稱為空白、不參與，並提示科別是空白

#### Scenario: 科別無法還原
- **WHEN** 舊批次沒有快照，且 `matrix_dept` 是空白
- **THEN** 科排名母群名稱為空白、科排名初始不參與，並顯示空白母群的提示

#### Scenario: 完全沒有排名學生列時停止
- **WHEN** 舊批次沒有快照，且 `rank_batch_student` 沒有該批學生
- **THEN** 確認清單不開啟，系統提示不會使用目前學生名單

### Requirement: 歷史批次清單標示快照種類
歷史清單 MUST 以 `rank_batch.id` 數字由大到小排列，重新載入時 MUST 保留原本選取的批次。清單 MUST 能分辨 JSON 快照、舊 XML 版本 1 與沒有快照。兩種都有時 MUST 標成 JSON。JSON 文件損壞或版本不是 1 時 MUST 仍標成 JSON，不得標成沒有快照。

#### Scenario: 三種標示
- **WHEN** 清單同時有 JSON 快照、只有 XML 版本 1，以及兩種都沒有的學期成績批次
- **THEN** 三者分別顯示快照有(JSON)、快照有(XML)與快照無，且識別較大的批次排在前面

### Requirement: 歷史來源原值還原後套用不排名預設
快照與無快照歷史清單在取得來源原值後，MUST 套用圖1不排名學生類別：符合者五種參與改為不參與，已還原名稱不變，且 MUST NOT 修改舊批次。

#### Scenario: 無快照學生符合目前的不排名類別
- **WHEN** 舊批次沒有快照，已還原班排名名稱的學生符合圖1不排名類別
- **THEN** 班排名名稱保留，五種初始參與為不參與，舊批次內容不變

#### Scenario: 快照參與被目前不排名類別改成初始不參與
- **WHEN** 快照記錄該生年排名為參與，且該生符合圖1目前的不排名類別
- **THEN** 年排名母群名稱仍是快照原值，初始參與為不參與，舊批次內容不變

### Requirement: 同一排名類型的多個母群名稱視為衝突
舊批次還原時，同一學生的同一排名類型若得到兩個以上不同母群名稱，系統 MUST NOT 任取其中一筆，也 MUST NOT 用目前學生的母群名稱取代。系統 MUST 在確認清單警示該學生、排名類型與每一個衝突名稱。該項 MUST 沒有選定母群且不參與。該生其他只有一個名稱的排名類型 MUST 照原資料還原。系統 MUST NOT 修改該舊批次。

#### Scenario: 班排名還原出兩個班名
- **WHEN** 同一學生的班排名在舊批次中同時得到「忠班」與「孝班」
- **THEN** 確認清單不選定班排名母群、班排名不參與，並警示這兩個名稱；年、科與類別中沒有衝突的項目仍照舊資料顯示

#### Scenario: 相同名稱的重複列不是衝突
- **WHEN** 同一學生的科排名只有「普通科」這個名稱，但舊明細有多列
- **THEN** 科排名母群名稱為「普通科」，且不產生多母群衝突警示

### Requirement: 沒有本次成績的歷史學生仍留在清單
由歷史批次還原的學生，即使本次計算期間沒有任何成績，MUST 仍留在確認清單。該項沒有成績時，計算 MUST NOT 為該項目產生該生的名次或把該生計入該項目人數。

#### Scenario: 歷史學生沒有本次科目成績
- **WHEN** 學生在歷史母群中且年排名為參與，但本次學年度學期沒有某科目成績
- **THEN** 該生仍顯示在確認清單，該科目的年排名沒有該生
