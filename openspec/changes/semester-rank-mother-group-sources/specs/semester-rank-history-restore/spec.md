# Spec Delta

## Purpose

定義如何依歷史期間選擇學期成績母群批次，以及有快照與沒有快照時如何還原母群且不拿目前學生資料填補缺口。2026-11-16 起，學期排名設定頁的歷史清單只接受考試名稱「學期成績」；定期評量批次不再列入，也不在下一步還原。

## ADDED Requirements

### Requirement: 歷史批次只列學期成績
系統 MUST 依歷史來源學年度、歷史來源學期，以及 `rank_batch.setting` 的「考試名稱」篩選母群批次。清單 MUST 包含已不是目前有效排名的舊批次，而且 MUST 只接受考試名稱為「學期成績」的批次。考試名稱是定期評量名稱、空白、沒有這個屬性，或無法辨識的批次，MUST NOT 進入清單；技職繁星屬於沒有考試名稱的這一類。系統 MUST NOT 接受全部 `rank_batch`。

清單文字 MUST 包含批次 ID、來源類型、學年度、學期、評量名稱、批次說明、年級與快照種類。來源類型只使用「學期成績」。評量名稱使用 `setting` 的考試名稱。排序 MUST 是 `rank_batch.id` 數字降冪。系統 MUST NOT 把這個順序顯示成建立時間排序。快照標示與歷史母群還原方式維持既有規則：有效 JSON、只有 XML、兩種都沒有時才讀 `rank_batch_student`。

#### Scenario: 114-2 只出現學期批次
- **WHEN** 歷史來源是 114 學年度第 2 學期，該期間有學期成績批次 285，以及定期評量批次 272 到 277
- **THEN** 清單只有批次 285，272 到 277 都不出現

#### Scenario: 同學年期有多個舊批次
- **WHEN** 同一歷史來源學年度與學期存在多筆考試名稱為「學期成績」的排名批次
- **THEN** 這些批次都出現在歷史來源清單，使用者可指定其中一筆，而且識別較大的排在前面

#### Scenario: 同期間的定期評量不可選
- **WHEN** 同一歷史期間同時有考試名稱「學期成績」的批次，以及考試名稱「期中考」的定期評量批次
- **THEN** 只有學期成績批次出現，期中考批次不在清單，也不能在下一步還原

#### Scenario: 技職繁星批次不出現
- **WHEN** 使用者開啟歷史母群清單
- **THEN** 沒有考試名稱的技職繁星批次不在清單中，其他無法辨識的批次也不在清單中

### Requirement: 歷史期間篩選批次且不額外改寫計算期間
歷史來源 MUST 啟用歷史學年度、歷史學期與批次選取，而且清單 MUST 只含與此期間相同的批次。其他來源 MUST 停用這三項並清除批次選取與批次識別。歷史期間與批次選取 MUST NOT 額外改寫計算期間。切換來源時，計算期間 MUST 依各來源既有政策處理。目前學生來源恢復系統期間並停用欄位。歷史與 Excel 的計算期間可編輯，且不被歷史批次期間改寫。

#### Scenario: 歷史期間與計算期間不同
- **WHEN** 本次計算期間是 115 學年度第 1 學期，歷史來源期間是 114 學年度第 2 學期，而且已選該期間的學期成績批次
- **THEN** 學生與分組來自 114-2 批次，學期成績只取畫面上方的 115-1，選取批次不改寫 115-1

#### Scenario: 切回目前學生來源
- **WHEN** 使用者從歷史來源改選目前學生，計算期間原本是 114 學年度第 2 學期，系統目前值是 115 學年度第 1 學期
- **THEN** 歷史控制項停用且批次選取被清除；計算期間恢復 115 學年度第 1 學期，學年度與學期欄位停用

#### Scenario: 切換 Excel 時不由歷史選取改寫計算期間
- **WHEN** 使用者在歷史來源把計算期間設為 114 學年度第 2 學期並選了 113-2 批次，再改選 Excel
- **THEN** 歷史控制項停用且批次選取被清除；計算期間仍是 114 學年度第 2 學期並可編輯

### Requirement: 期間變更、失敗與零筆都清除舊選取
使用者改變歷史學年度或學期後，系統 MUST 清除原先選取的批次與批次識別，並依新期間重載清單。有學期成績批次時 MUST 讓使用者重新選擇，不得沿用上一筆。查詢失敗或沒有學期成績批次時，MUST 清除殘留選取。沒有批次時 MUST 顯示「此期間無學期成績批次」，並停用下一步。上方計算期間 MUST 維持使用者原先選好的值。

#### Scenario: 切換歷史學期後不保留舊批次
- **WHEN** 使用者已選 114-2 的一批，計算期間是 115-1，再把歷史學期改成 1
- **THEN** 該批選取與批次識別被清除，清單改為 114-1 的學期成績批次，計算期間仍是 115-1

#### Scenario: 該期間只有定期評量
- **WHEN** 歷史期間沒有考試名稱為「學期成績」的批次，只有定期評量批次
- **THEN** 清單是空的，畫面顯示「此期間無學期成績批次」，下一步停用，而且不進入確認清單

### Requirement: 下一步再次核對歷史期間與批次類型
按下下一步時，所選批次的學年度、學期 MUST 與畫面上的歷史期間一致，而且 `setting` 考試名稱 MUST 是「學期成績」。期間不一致或類型不是學期成績時 MUST 停止，不開啟確認清單，也不讀取學生。通過後 MUST 用該批次取得學生與分組，並用畫面上方的計算期間取得學期成績。選取批次 MUST NOT 把該批期間寫回歷史篩選條件或計算期間。

#### Scenario: 殘留選取與歷史期間不一致
- **WHEN** 畫面上的歷史期間已是 113-1，選取仍指到 113-2 的批次
- **THEN** 下一步停止，不開啟確認清單，計算期間也不被改成 113-2

### Requirement: 歷史期間初始使用系統預設期間
首次開啟畫面時，歷史來源學年度與歷史來源學期 MUST 使用系統預設學年度及學期，與初始計算期間相同。選歷史來源後，批次 MUST 依歷史兩欄的實際值同時比對篩選，不得顯示其他期間的批次。後續手動變更歷史期間 MUST NOT 改寫計算期間。切回保留政策本次維持現有控制項行為，不另新增跨次記憶；離開歷史來源仍清除批次選取。

#### Scenario: 系統預設 114-2
- **WHEN** 系統預設學年度為 114、學期為 2，首次開啟畫面並切到歷史來源
- **THEN** 歷史兩欄初始為 114、2，批次只列 114-2 的學期成績批次

### Requirement: 有效 JSON 維持既有還原
歷史批次 MUST 先讀 `rank_batch.extension` 的 `MotherGroupSnapshot`。JSON 快照可讀時，系統 MUST 以它作為來源原值，包含全部學生、姓名、五種母群名稱與五種參與狀態，並維持既有還原規則。讀取 MUST NOT 用目前班級、科別或標籤重建母群，也 MUST NOT 修改該舊批次。圖1不排名預設在這份 JSON 原值之後另套用。只有 XML、或兩種快照都沒有時，MUST NOT 套用這條 JSON 規則。

#### Scenario: JSON 快照原值先被保留
- **WHEN** 所選批次的 JSON 快照記錄某生有班排名母群名稱且班排名不參與，且該生不符合圖1不排名類別
- **THEN** 確認清單顯示該名稱與姓名，班排名初始狀態為不參與，舊批次內容不變

### Requirement: 壞掉的 JSON 快照不可改走其他來源
extension 不是 JSON 陣列、`MotherGroupSnapshot` 版本不是整數 1、學生內容無法還原、學生清單是空的，或同名快照超過一筆時，系統 MUST 顯示具體原因並停止。這種情況 MUST NOT 改讀舊 XML、`rank_batch_student` 或目前學生。extension 是 null、空白、`[]` 或有效陣列中沒有這個名稱時，才 MUST 繼續讀舊 XML。

#### Scenario: 版本不符時停止
- **WHEN** extension 有一筆 `MotherGroupSnapshot` 且版本不是整數 1，setting 另有可讀的 XML 版本 1
- **THEN** 確認清單不開啟，也不使用該 XML 快照

#### Scenario: 沒有 JSON 才繼續讀 XML
- **WHEN** extension 是空陣列，setting 有一筆可讀的 XML 版本 1
- **THEN** 系統讀取該 XML 的學生清單，不把這筆當成損壞的 JSON，也不改查 `rank_batch_student`

### Requirement: 只有 XML 時讀取快照內的完整學生清單
沒有有效 JSON、且 setting 恰有一筆可讀的 XML 版本 1 時，系統 MUST 以該 XML 的完整學生清單建立確認清單，不得改查 `rank_batch_student`。年、科、班 MUST NOT 沿用 XML 的歷史參與狀態。不符合不排名類別者，這三項 MUST 預設參與。符合者不自動改成參與；這只是暫時保留既有不排名效果，不代表優先序已核准。類別一與類別二 MUST 維持既有規則。系統 MUST NOT 用目前學籍補母群名稱。XML 重複或無法還原時 MUST 停止，不得改查排名學生。

#### Scenario: XML 有 A、B 而排名學生列不完整
- **WHEN** extension 沒有 JSON，XML 版本 1 有學生 A 與 B，且 `rank_batch_student` 只有 A 或完全沒有該批學生
- **THEN** 確認清單仍同時有 A 與 B，名稱來自 XML，且不使用目前學籍補名稱

#### Scenario: 不符合不排名者年科班改為參與
- **WHEN** XML 記錄某生年、科、班都不參與，該生不符合不排名類別，班名是「高一甲」
- **THEN** 班名仍是「高一甲」，年、科、班初始參與，不沿用 XML 的參與旗標

### Requirement: 兩種快照都沒有時才用排名學生
JSON 與 XML 版本 1 都不存在時，系統 MUST 以該批 `rank_batch_student` 建立清單。年、科、班的參與規則與只有 XML 時相同，且 MUST NOT 用目前學籍補名稱。沒有排名學生列時 MUST 停止，不開啟空白確認清單，也不改用目前學生。

#### Scenario: 完全沒有快照也沒有排名學生列時停止
- **WHEN** 舊批次沒有 JSON、沒有 XML 版本 1，且 `rank_batch_student` 沒有該批學生
- **THEN** 確認清單不開啟，系統提示不會使用目前學生名單

### Requirement: 第二畫面名稱沿用既有年級邊界
沒有 JSON 時，第二畫面顯示的母群名稱 MUST 作為分組依據。年、科、班名稱相同、且不符合不排名類別的學生 MUST 歸入同一母群並預設參與。系統 MUST NOT 改寫年、科排名已含年級的窗口，也 MUST NOT 改寫班排名只依班名的窗口。系統 MUST NOT 把不同年級的同名班級或科別收成一個新名稱，也 MUST NOT 用目前學籍補名稱。

#### Scenario: 同名班在既有名稱內歸成同一母群
- **WHEN** 沒有 JSON 的清單有兩名不符合不排名類別的學生，班排名名稱都是「高一甲」，年排名名稱都是「1年級」
- **THEN** 兩名學生的班排名母群名稱都是「高一甲」，而且班排名預設參與

#### Scenario: 不同年級的同名班不被收成新名稱
- **WHEN** 沒有 JSON 的清單同時有班排名名稱「高一甲」與「高二甲」
- **THEN** 確認清單保留這兩個名稱，不把他們改成同一個「甲」

### Requirement: 空白或衝突母群留在第二畫面
沒有 JSON 時，年、科、班名稱空白或同一學生同一排名類型有多個名稱，系統 MUST NOT 跳出 MessageBox，MUST NOT 移除學生，也 MUST NOT 因空白或衝突自動取消這三項參與。不符合不排名類別者，這三項 MUST 維持預設參與。衝突 MUST NOT 任取一個名稱，MUST NOT 用目前學籍補名稱，也 MUST NOT 另外開放母群名稱編輯。衝突名稱 MUST 留在確認清單供使用者查看。類別一、類別二的空白與衝突 MUST 維持既有規則。使用者 MUST 能在第二畫面調整未被既有衝突鎖定的年、科、班參與勾選。計算 MUST 使用第二畫面最終確認的名稱與參與狀態。

#### Scenario: 空白科別仍留在清單且年科班參與
- **WHEN** 沒有 JSON 的清單中，一名不符合不排名類別的學生，科排名名稱是空白
- **THEN** 該生留在確認清單，科排名名稱維持空白，年、科、班初始參與，而且沒有空白母群的 MessageBox

#### Scenario: 班名衝突不取消參與
- **WHEN** 沒有 JSON 的同一名不符合不排名類別的學生，班排名同時得到「忠班」與「孝班」
- **THEN** 確認清單不選定其中一個班名、不移除該生、不跳出 MessageBox，班排名初始參與，使用者也能調整這個參與勾選

### Requirement: 歷史批次清單標示快照種類
歷史清單 MUST 以 `rank_batch.id` 數字由大到小排列，重新載入時 MUST 保留原本選取的批次。清單 MUST 能分辨 JSON 快照、舊 XML 版本 1 與沒有快照。兩種都有時 MUST 標成 JSON。JSON 文件損壞或版本不是 1 時 MUST 仍標成 JSON，不得標成沒有快照。

#### Scenario: 三種標示
- **WHEN** 清單同時有 JSON 快照、只有 XML 版本 1，以及兩種都沒有的學期成績批次
- **THEN** 三者分別顯示快照有(JSON)、快照有(XML)與快照無，且識別較大的批次排在前面

### Requirement: 有效 JSON 還原後套用不排名預設
有效 JSON 歷史清單在取得來源原值後，MUST 套用圖1不排名學生類別：符合者五種參與改為不參與，已還原名稱不變，且 MUST NOT 修改舊批次。沒有 JSON 時，不排名類別對年、科、班的優先序尚未核准。核准前，系統暫時保留既有效果：符合者的年、科、班不因全參與預設改成參與；不符合者套用全參與。這不是已核准政策。類別一與類別二 MUST 仍依既有規則。

#### Scenario: 無 JSON 的符合者暫時維持不參與
- **WHEN** 舊批次沒有 JSON，已還原班排名名稱的學生符合圖1不排名類別
- **THEN** 班排名名稱保留，年、科、班初始不參與，類別一與類別二仍依既有規則，舊批次內容不變，且這不代表優先序已核准

#### Scenario: JSON 快照參與被目前不排名類別改成初始不參與
- **WHEN** 有效 JSON 記錄該生年排名為參與，且該生符合圖1目前的不排名類別
- **THEN** 年排名母群名稱仍是快照原值，初始參與為不參與，舊批次內容不變

### Requirement: 同一排名類型的多個母群名稱視為衝突
舊批次還原時，同一學生的同一排名類型若得到兩個以上不同母群名稱，系統 MUST NOT 任取其中一筆，也 MUST NOT 用目前學生的母群名稱取代。系統 MUST 在確認清單列出該學生、排名類型與每一個衝突名稱。該項 MUST 沒有選定母群。有效 JSON 的衝突項目 MUST 不參與。沒有 JSON、且不符合不排名類別的年、科、班衝突 MUST 維持預設參與，且 MUST NOT 用 MessageBox 警示。符合者不因這次預設改成參與。類別一、類別二衝突 MUST 維持既有不參與規則。該生其他只有一個名稱的排名類型 MUST 照原資料還原。系統 MUST NOT 修改該舊批次。

#### Scenario: 沒有 JSON 的班排名還原出兩個班名
- **WHEN** 沒有 JSON 的批次中，同一名不符合不排名類別的學生，班排名同時得到「忠班」與「孝班」
- **THEN** 確認清單不選定班排名母群，班排名仍初始參與，衝突欄列出這兩個名稱，而且沒有 MessageBox

#### Scenario: 有效 JSON 的班排名衝突維持不參與
- **WHEN** 有效 JSON 的同一學生班排名同時得到「忠班」與「孝班」
- **THEN** 確認清單不選定班排名母群，班排名不參與，並列出這兩個名稱

#### Scenario: 相同名稱的重複列不是衝突
- **WHEN** 同一學生的科排名只有「普通科」這個名稱，但舊明細有多列
- **THEN** 科排名母群名稱為「普通科」，且不產生多母群衝突警示

### Requirement: 沒有本次成績的歷史學生仍留在清單
由歷史批次還原的學生，即使本次計算期間沒有任何成績，MUST 仍留在確認清單。該項沒有成績時，計算 MUST NOT 為該項目產生該生的名次或把該生計入該項目人數。

#### Scenario: 歷史學生沒有本次科目成績
- **WHEN** 學生在歷史母群中且年排名為參與，但本次學年度學期沒有某科目成績
- **THEN** 該生仍顯示在確認清單，該科目的年排名沒有該生

### Requirement: 無快照的排名學生必須分頁讀取
沒有 JSON 與 XML 版本 1 時，系統 MUST 仍以該批 `rank_batch_student` 還原，而且 MUST 維持 JSON 快照、舊 XML 快照、排名學生這個順序。查詢 MUST 以 `ref_batch_id` 限定所選批次。系統 MUST 先以單一聚合結果確認該批 `id` 唯一；不唯一時 MUST 停止，不得用它當游標。確認唯一後，MUST 只取母群還原所需欄位，以 `id` 為游標、`ORDER BY id LIMIT ...` 依序讀取。1.0.0.64 的 `Java heap space` 來自一次讀完整批的 `SelectBatchStudentSql()`；期間核對、設定讀取與 `StudentTag.SelectAll()` 不是這次的失敗呼叫。

#### Scenario: id 不唯一時不分頁
- **WHEN** 所選批次的 `rank_batch_student.id` 有重複
- **THEN** 系統停止，不依 `id` 游標讀取，也不開啟確認清單

#### Scenario: 有 JSON 的批次不讀排名學生
- **WHEN** 所選批次的 JSON 快照可還原，例如批次 285
- **THEN** 系統用 JSON 建立確認清單，不送出 `rank_batch_student` 分頁查詢

### Requirement: 全部分頁成功後才沿用既有合併
全部頁都成功後，系統 MUST 把各頁列合成一份，再沿用既有的依學生合併、排序、五種母群名稱、衝突判定與參與預設。同一學生分散在不同頁的列 MUST 一起合併。系統 MUST NOT 在每一頁各自產生確認清單。

#### Scenario: 同一學生的兩頁列在讀完後合併
- **WHEN** 無快照批次的排名學生以每頁 1 列讀取，第 1 頁與第 2 頁是同一學生，班排名名稱分別是「忠班」與「孝班」
- **THEN** 確認清單只有該生一列，班排名同時保留這兩個名稱，並沿用無 JSON 的參與預設，不在讀第 1 頁後就開啟確認清單

### Requirement: 歷史還原按步驟記錄且失敗不進入確認頁
下一步讀歷史批次時，系統 MUST 分開記錄期間核對、批次設定與快照讀取、學生標籤讀取、歷史學生查詢。每段 MUST 記錄批次 ID、步驟、耗時、回傳筆數與例外。紀錄 MUST NOT 包含學生姓名、學號、學生識別或母群名稱。設定與快照只可記錄字元數，MUST NOT 記錄欄位內容。

任一頁或上述任一步失敗時，系統 MUST 捨棄本次已讀到的排名學生與母群結果，不得顯示部分母群，也不得進入排名計算。畫面 MUST 留在設定頁，訊息 MUST 包含批次 ID 與失敗步驟。系統 MUST 清除失敗的那一筆選取、停用下一步，並保留清單裡的其他批次供重新選擇。

#### Scenario: 第二頁失敗時不開啟確認清單
- **WHEN** 無快照批次已讀到第 1 頁，第 2 頁發生 `Java heap space`
- **THEN** 確認清單不開啟、計算不開始，畫面留在設定頁並顯示該批次 ID 與歷史學生步驟，失敗選取被清除，下一步停用，其他批次仍可再選

#### Scenario: 91 與 283 必須逐項還原而不是只比人數
- **WHEN** 在現有 Server 設定下讀取無快照批次 91 或 283
- **THEN** 讀取完成後，依同一批 `rank_batch_student` 與既有合併規則核對每位學生的識別、五種母群名稱與參與狀態；重複列與衝突名稱也必須與合併結果一致。只比對總人數不算通過

#### Scenario: 285 維持 JSON 確認頁
- **WHEN** 在同一環境選取有 JSON 快照的批次 285 並按下一步
- **THEN** 確認頁開啟，母群總數是 1,363 人
