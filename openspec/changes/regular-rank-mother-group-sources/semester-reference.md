# 學期 OpenSpec 對照與定期評量調整

日期：2026-10-30。此文件記錄相對學期 OpenSpec 的依據。使用者已於同日核准 regular-decisions.md 的建議方案並授權 Apply；D02、D05、D06、D07、D08 採用本檔參照方案。本檔不修改學期 Change。

來源根目錄：`../semester-rank-mother-group-sources/`。以下引用該目錄中 spec 的 Requirement 名稱，方便避開後續行號變動。

## D01：目前來源與歷史目標期間

來源：`specs/semester-rank-mother-group-source/spec.md`「計算期間可選且與母群來源期間分開」。學期 spec 允許選期間，但實際 `CalculateSemesterAssessmentRank.ApplyCalculationPeriodEditors` 對目前來源恢復並鎖系統期間，兩者不完全一致。

已核准：三種來源都可選歷年，預設系統期間，目前來源標明目前母群＋目標成績。不將學期程式鎖定行為稱為學期規格。

## D02：歷史來源類型

來源：`specs/semester-rank-history-restore/spec.md`「列出全部歷史學期固定排名批次」。學期只允許學期來源，包含已失效舊批次。

定期參照方案：只列定期評量批次，包含失效批次，排除學期與技職繁星。不能只以名稱不是「學期成績」判定定期；必須核對既有批次設定及排名類型，歧義提示。

## D03：來源與目標分離

來源：mother-group-source「計算期間可選且與母群來源期間分開」，情境 113-2 來源計算 114-2。

已核准：來源與目標期間分離，來源考試與目標考試也可以不同，兩組同時顯示。這是定期新增條件，不由學期情境自行推出。

## D04：三組採計科目

學期沒有定期評量 exam／三組採計科目的同等規格。不能直接類推已核准。

已核准：按目標期間、目標 exam ID、來源學生修課取得科目；先載入母群再確認科目，條件變更後重載。一般與類別科目、領域原有交集不改。來源與目標考試可以不同。

## D05：無快照還原

來源：history-restore「無快照時只從排名學生列還原」「同一排名類型的多個母群名稱視為衝突」。

定期參照方案：JSON → 舊 XML → rank_batch_student。JSON 與 XML 母群快照均不存在時才降級。快照存在但損壞、重複、版本不支援或內容無法還原時停止，不當作不存在；舊 XML 損壞時不回退 rank_batch_student。降級只用 matrix_grade/dept/class/tag1/tag2；非空名稱預設參與，空白不參與並先提示。不得用目前學籍或 rank_detail 補名；無學生列停止。衝突留空且不參與，顯示每個衝突名。

定期舊版未指定 matrix_dept 寫入，須驗證實際欄位／內容；缺漏明示為降級。這些預設不是原始參與旗標的精確恢復。學號姓名可左連目前主檔，不能因此改母群。

## D06：沒有成績

來源：history-restore「沒有本次成績的歷史學生仍留在清單」及 calculation「沒有成績不產生該項名次」。

定期參照方案：清單與完整 Snapshot 保留學生；沒有該項有效成績不產生該項明細、不計入該項排名分母，不在第二畫面大量預查完整成績。

## D07：不排名類別優先順序

來源：participation「三種來源都先保留原值再套用不排名預設」及 history-restore「歷史來源原值還原後套用不排名預設」。

定期參照方案：目前／Excel／歷史都先取得來源名稱與旗標，再依本次目前標籤套不排名預設，符合者五旗標初始 false；可在第二畫面覆寫。計算不再重套預設，舊批次不變。

此處更正先前對話的「歷史旗標不被目前標籤覆寫」建議。名稱保留與旗標套用是不同動作。

## D08：Excel

來源：`specs/semester-rank-excel-exchange/spec.md` 全部 Requirements。

定期參照方案：同 13 欄、相同順序；狀態只接受一般／延修／休學／輟學／畢業或離校／刪除，參與只接受參與／不參與。學號保留前導零，以學號＋狀態查得唯一 student.id；任一列錯誤整份阻擋。姓名不同使用主檔姓名並警告。相同學號不同狀態且不同 ID 可並存。

匯出缺狀態時按 student.id 批次查目前狀態，不當作歷史狀態；查詢不能改母群。匯出入原值可往返，但依 D07 重套本次不排名預設後旗標可能不同，不能要求最終旗標無條件一致。

## D09：歷史人工加人

來源：participation「歷史清單可加入目前學生母群」「歷史加入學生仍只依學號」，design 的「三項歷史來源遺留」。

定期參照方案：提供加入學生，以學號查詢，多筆阻擋，帶目前五種母群與年級、名稱唯讀、旗標可改。這條路徑與 Excel 學號＋狀態不同。

明列學期遺留：不同 ID 相同學號可能被既有清單去重攔下；無班級時年母群空白但初始參與 true；加入時讀全部標籤。定期若改善，須先分析共用影響，不能順帶修改學期。無法解析年級者保留清單／快照、不進任何排名且計算前提示。已核准：歷史加人依學號、不加狀態篩選，不套目前來源的一般＋延修限制；既有相同學號去重保留。

此方案取代先前「第一版暫不開放加人」建議。

## D10：發布與失效

來源：calculation「停用與啟用在同一個交易完成」「沒有可計算年級時不開始計算」「語句超過閘道則停止公布」，design 第 6 節及工作副本／確認流程。

定期參照方案：單次 Select 的單一語句、批次 ID 由 RETURNING 供句內使用，全部選定且可計算年級同成同敗。失效限目標期間、實際目標 exam ID、對應年級與定期 item_type，不直接搬學期 -1／學期前綴。超過閘道或約束不允許時停止，不逐年級提交、不刪舊批次。

空可計算年級在確認／組態 Save 前停止。學期 spec 未完整定義零明細與跨用戶端並行；這兩項已按 regular-decisions.md 核准：全體無明細或任一實際取代年級無新明細時整次失敗，同一目標期間與 exam ID 的發布互斥。不能把本地按鈕防重入當作資料庫並行保護。鎖機制仍須獨立測試庫證明。

## 一併參照的共同規則

- 五種母群名稱唯讀，旗標獨立、可批次改；恢復為入頁初始值，統計不查成績。
- JSON v1 全清單、來源 enum、歷史來源批次 ID、年級可解析否則 null；不保存狀態、座號、識別班級或不排名類別。
- SQL 學生輸入與 Snapshot 來自同一工作副本；可研究沿用 JSONB 輸入，但定期 SQL 接入需專用驗證，不直接套學期字串替換器。
- 組態 Save 在確認後、排名 SQL 前，失敗不隨排名回滾；確認文案明示。取消不 Save，不寫排名。
- 同一份副本供確認範圍、SQL 與快照，執行中事件拒絕修改，結束恢復原本可用／可見狀態。
- 學期現有驗收未完成項不因本次參照補勾；兩者各自保留驗收證據。
